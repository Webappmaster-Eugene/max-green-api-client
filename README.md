# Max — React-клиент GREEN-API

Клиент текстовых сообщений MAX: существующие чаты, контакты, поиск, история,
отправка, ответы и статусы доставки. На телефоне список и переписка открываются
отдельными экранами; на компьютере доступны рядом.

Сайт: **https://max.nadtocheev.ru**.

## Локальный запуск

Node.js 22.12 или новее:

```sh
npm ci
npm run build
npm start
```

Открыть http://127.0.0.1:18792. PostgreSQL, Telegram, LLM и Docker не нужны.
Для разработки в двух терминалах: `npm run dev` и `npm run dev:ui`.
При этом установить `PUBLIC_ORIGIN=http://localhost:5174` для backend.

## Подключение аккаунта

1. Создайте инстанс **MAX** в https://console.green-api.com/ и авторизуйте его
   владельцем аккаунта по QR-коду.
2. Оставьте `webhookUrl` пустым. Включите `incomingWebhook`, `outgoingWebhook`,
   `outgoingMessageWebhook` и `outgoingAPIMessageWebhook`.
3. Введите в клиент `apiUrl`, `idInstance`, `apiTokenInstance`; подтвердите
   разрешение владельца на чтение чатов и отправку сообщений от его имени.
4. Выберите существующий чат или контакт. Для нового получателя есть поиск
   по номеру РФ/Беларуси через кнопку «＋».

Ключ GREEN-API вводится в форме, не в URL или переменных окружения сайта.
Он остаётся в RAM backend, никогда не возвращается браузеру, не сохраняется
в localStorage, БД или журналах. Каждому посетителю выделяется изолированная
HttpOnly-cookie с SameSite=Strict, Secure в HTTPS. Подключение живёт восемь
часов или до отключения/перезапуска сервера. Для повторного подключения ключ
потребуется снова.

Для одного инстанса должен работать один потребитель очереди уведомлений.
Отключите тот же инстанс в Mini App Советника и закройте чужие клиенты перед
подключением здесь. Сайт и Mini App имеют независимые сессии, но используют
одинаковый React-компонент и HTTP-движок GREEN-API.

## Как работает переписка

Backend проверяет `getStateInstance` и `getSettings`, загружает `getChats` и
`getContacts`. Открытие диалога вызывает `getChatHistory` (100 последних событий);
кнопка загрузки более ранних увеличивает выборку до 5000. История ограничена
провайдером последними тремя месяцами. Поиск выполняется по уже полученному списку,
без запросов на каждый ввод символа.

`sendMessage` сначала возвращает статус «В очереди». «Доставлено» и «Прочитано»
появляются только из уведомлений `outgoingMessageStatus`.
`receiveNotification` опрашивается последовательно, затем вызывается
`deleteNotification`. Повторные события не дублируются. При неопределённом
результате отправки автоматического повторного сообщения нет. Request ID
позволяет безопасно повторить запрос, если ответ нашего сервера потерялся.

Входящие/исходящие тексты из приложения телефона также принимаются при включённых
уведомлениях. Вложения в истории отображаются заглушкой; отправка файлов и
управление участниками групп не входят в текстовое тестовое задание.

Защитные ограничения: до 50 подключений на процесс, до 10000 контактов/чатов,
до 10000 сообщений в памяти сессии и до 300 попыток отправки. Между отправками
три секунды. Это не отменяет квоты MAX Developer (три чата) или ограничения MAX.
Опрос выполняется только на открытой видимой странице; фоновые push-уведомления
и постоянное хранение истории не реализованы.

## Проверки

```sh
npm test
npm run test:ui
npm run build
npx playwright install chromium
npm run test:e2e
```

Тесты не требуют настоящего аккаунта и не отправляют реальные сообщения. E2E
проверяет контакты, историю, отправку, входящий ответ, статус доставки и
мобильный переход назад на подменённом API. Скриншоты содержат демонстрационные данные.

## Dokploy

Создайте Application из этого Git-репозитория, ветка `main`, тип сборки
Dockerfile. Домен `max.nadtocheev.ru`, порт **3000**, HTTPS и Let's Encrypt.
Задайте `PUBLIC_ORIGIN=https://max.nadtocheev.ru`. Запуск в контейнере от пользователя
node; никаких портов управления или секретов провайдера в образе нет.

В этом репозитории только код клиента, без личных контактов, ключей, конфигов
Dokploy и остальной инфраструктуры Советника.
