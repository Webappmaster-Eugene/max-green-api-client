Как защищены доступ и данные.

Публичной регистрации нет. Пользователей создаёт администратор.
Запросы MAX и управления пользователями требуют входа на сайт.
Администратор может выдать или отозвать доступ, но API не позволяет
ему читать чужую переписку.

На HTTPS токен входа находится в cookie `__Host-max-auth`.
Флаги Secure, HttpOnly и SameSite=Strict ограничивают его передачу
и закрывают доступ из JavaScript. Cookie действует 365 дней
и продлевается при использовании. JWT не выдаётся в JSON
и не записывается в localStorage или sessionStorage.

Сервер проверяет подпись, срок токена и его назначение,
а также запись сессии и статус пользователя. Выход отзывает сессию.
Смена пароля или запрет доступа отзывает все сессии пользователя.
Реестр сессий сохраняется на диске, поэтому отзыв действует
и после перезапуска сервера.

Пароли хранятся как scrypt-хеши с отдельной случайной солью.
Исходный пароль по такому хешу не восстанавливается обычным чтением файла.
Минимальная длина нового пароля - 12 символов.
Сервер не запускается без ключа подписи и исправного хранилища.
Повреждение файла пользователей не создаёт новый пустой набор учётных записей.

Изменяющие запросы требуют CSRF-токен в заголовке.
Это дополнительная проверка, которая мешает чужому сайту выполнять
действия с cookie пользователя. Вход также требует заголовок клиента
и совпадение адреса сайта в Origin. Запросы с чужого сайта отклоняются.
CORS не включён.

Попытки входа ограничены по IP и логину. Неверный пароль,
неизвестный и отключённый пользователь дают одинаковую ошибку.
Другие запросы и отправка сообщений тоже ограничены по частоте.
IP берётся из последнего адреса `X-Forwarded-For`, добавленного
доверенным прокси. Порт контейнера не должен быть доступен в обход этого прокси.

Zod проверяет JSON, поля формы, параметры URL и ответы GREEN-API.
Размер JSON ограничен 32 КиБ, файла - 10 МБ.
Для формы загрузки есть небольшой запас на служебные данные.
Нельзя передать другой `owner` или `userId` в запросе и сменить владельца:
сервер получает его из проверенной сессии.

Для истории, цитат, пересылки, редактирования, удаления, реакций
и файлов проверяется принадлежность чата и сообщения текущему подключению.
Знание чужого `connectionId` или `messageId` не открывает доступ к данным.

Ключ GREEN-API сохраняется на сервере в зашифрованном файле.
Используется AES-256-GCM, который также обнаруживает изменение содержимого.
Ключ шифрования создаётся случайно и хранится в `DATA_DIR` с правами 0600.
Браузер не получает сохранённый ключ провайдера. При отключении MAX
или отзыве доступа ключ удаляется, адреса и номер инстанса остаются.

Резервная копия должна включать файлы `.enc` и соответствующие `.key`.
Доступ к ней нужно ограничить так же, как к рабочим данным.
Полные адреса запросов с ключом GREEN-API и исходные тексты ошибок
провайдера не выдаются браузеру и не пишутся в журнал.
Отзыв доступа отменяет незавершённые запросы. Сообщение, которое
провайдер уже принял, может быть отправлено и после отмены.

Адреса API и загрузки принимаются только для разрешённых HTTPS-серверов
GREEN-API. Переходы по перенаправлениям запрещены. Ссылки файлов
принимаются только с разрешённых хранилищ GREEN-API и Yandex Cloud,
включая `media`, `mediain`, `mediaout` и `sw-media` с номером кластера.
Пользователь не может задать произвольную ссылку для скачивания.
Сервер берёт её из проверенного сообщения пользователя.

Скачивание ограничено 10 МБ, даже если сервер файла не сообщил размер.
Файл отдаётся как `application/octet-stream` с предложением скачивания.
Заголовки запрещают угадывать тип и исполнять содержимое как страницу.
Фото, видео и аудио открываются только для разрешённых типов.
SVG, HTML, скрипты и исполняемые файлы нельзя прикрепить.
Антивирусной проверки нет.

React выводит сообщения как текст и не выполняет HTML из переписки.
Политика CSP ограничивает источники скриптов, подключений, файлов
и шрифтов. Встраивание сайта в чужую страницу запрещено.
Для Mantine разрешены встроенные стили. Ответы API не кэшируются.

Docker запускает приложение от пользователя node.
Секреты передаются через закрытые настройки Dokploy.
`.env*`, файл начального пароля и `data/` исключены из Git и сборки Docker.
Постоянный volume должен быть доступен приложению и администратору сервера.

Клиент рассчитан на небольшой закрытый сервис с одной копией приложения.
Вход со вторым фактором, восстановление пароля по почте, отдельный журнал
действий и общие ограничения для нескольких серверов не реализованы.
