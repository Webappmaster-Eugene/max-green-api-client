# Проверка требований и функциональности

Дата проверки: 6 октября 2026 года. Проверенная версия приложения: `aed21a5`.
Источником требований служит
[исходное тестовое задание](https://drive.google.com/file/d/1Ut39kkIs0QK-swnCsIPJc6pNqVIVGOD2/view).

## Соответствие ТЗ

| Требование                                   | Реализация и результат проверки                                                                                                                    |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Интерфейс отправки и получения сообщений MAX | Самостоятельный сайт и Mini App; диалог показывает исходящие сообщения и входящие ответы                                                           |
| GREEN-API                                    | Серверный клиент `src/max/client.ts` обращается к API инстанса MAX                                                                                 |
| Отправка и получение текста                  | Реализованы; модульные и браузерные тесты проверяют отправку, входящий ответ и статус доставки с подменённым API провайдера                        |
| Внешний вид чата MAX как прототип            | Список диалогов и область переписки, входящие/исходящие сообщения, поле ввода; отдельная компоновка для телефона                                   |
| Простой интерфейс с минимальными функциями   | Базовая переписка доступна напрямую; набор возможностей расширен по пожеланию владельца проекта, поэтому он больше исходного минимального варианта |
| Отправка через SendMessage                   | Используется `sendMessage`; проверены payload и защита от повторной отправки одного запроса                                                        |
| Получение через HTTP API                     | Используются `receiveNotification` и `deleteNotification`; тест проверяет обработку ответа, дубликатов и подтверждение уведомления                 |
| React                                        | React, Mantine и frontend по FSD                                                                                                                   |

Ввод реквизитов GREEN-API и создание чата по номеру телефона реализованы.
При первом подключении нужны адреса API из кабинета, номер инстанса и ключ.
После явного отключения сохранённого инстанса достаточно ключа. Подключение
по одному ключу не означает автоматическое определение неизвестного инстанса.

Код опубликован в этом репозитории, инструкция локального запуска находится
в [DEPLOYMENT.md](DEPLOYMENT.md), сервис — на
[max.nadtocheev.ru](https://max.nadtocheev.ru).

## Что проверено

- 31 серверный тест: авторизация, CSRF, изоляция пользователей, отзыв доступа,
  сохранение сессий, контракты, сообщения, история и безопасность вложений.
- 10 браузерных сценариев сайта на компьютере и телефоне: вход/выход, контакты,
  ответы с цитатой, редактирование, подтверждение удаления, отправка файла,
  реакции, поиск и восстановление подключения. Авторизация настоящая локальная;
  MAX API в этих сценариях подменён.
- На рабочем сайте с настоящим аккаунтом: открытие существующей переписки,
  показ реальной фотографии и скачивание фотографии и документа через
  защищённый маршрут. Ошибок JavaScript в этом сценарии не обнаружено.
- На рабочем Mini App при ширине 390 и 1280: настоящая проверка подписанных Telegram
  данных, отказ для анонимного запроса и неверной подписи, восстановление после
  перезагрузки и сбоя, вход по одному ключу. Данные MAX в UI подменены;
  проверка выполнялась в headless-браузере, а не в окне приложения Telegram.
- Локальная подготовка: создание новых приватных настроек и отказ от перезаписи
  существующих настроек; typecheck, проверка FSD и аудит runtime-зависимостей.

В рамках этой проверки новые сообщения реальным получателям не отправлялись,
уведомления провайдера не подтверждались. Полный приёмочный цикл с живым
получателем и реальные операции редактирования, удаления, реакций, пересылки
и загрузки файлов нельзя считать подтверждёнными только по автоматическим тестам.
Сценарий ручной проверки приведён в
[инструкции запуска](DEPLOYMENT.md#подключение-green-api-и-первая-переписка).

## Возможности сверх ТЗ и ограничения

Реализованы существующие чаты и контакты, просмотр групповой переписки,
поиск, история, файлы, просмотр фото/видео/аудио, цитаты, пересылка,
редактирование и удаление собственных сообщений, реакции, отметка прочтения,
экспорт загруженной истории, темы и постоянное сохранение подключения.

Это собственный клиент переписки, а не полная копия официального MAX.
Звонки, создание групп и управление участниками, запись голосовых сообщений,
фоновые push при закрытом сайте и постоянный архив всей переписки не реализованы.
История ограничена возможностями GREEN-API; файлы в клиенте ограничены 10 МБ.

Сайт и Mini App имеют независимые сохранённые подключения. Для одного инстанса
нужен один потребитель очереди: одновременное чтение уведомлений двумя клиентами
может разделить ответы между ними. Синхронная работа нескольких клиентов через
единый сервер уведомлений в текущую архитектуру не входит.
