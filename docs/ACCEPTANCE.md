Проверка ТЗ и основных сценариев.

Проверка выполнена 6 октября 2026 года для версии `aed21a5`.
Требования взяты из
[исходного задания](https://drive.google.com/file/d/1Ut39kkIs0QK-swnCsIPJc6pNqVIVGOD2/view).
В нём нужен простой React-чат для отправки и получения текста в MAX
через GREEN-API. Пользователь подключает инстанс, создаёт чат
по номеру телефона, отправляет сообщение и видит ответ.

Эти функции реализованы. Отправка использует `sendMessage`,
получение - `receiveNotification` и `deleteNotification`.
Интерфейс состоит из списка диалогов и переписки, как в веб-чате MAX.
Для телефона есть отдельное расположение экранов.
Дополнительные функции добавлены по пожеланию владельца проекта.

При первом подключении вводятся адреса API и файлов, номер инстанса
и ключ. После явного отключения сохранённого инстанса достаточно ключа.
Клиент не определяет неизвестный инстанс по одному ключу.
Исходники опубликованы в этом репозитории,
[инструкция запуска](DEPLOYMENT.md) доступна в GitHub,
[рабочий сайт](https://max.nadtocheev.ru) размещён в интернете.

Прошёл 31 серверный тест. Они проверяют вход, защиту запросов,
права пользователей, отзыв доступа, сохранение сессий, сообщения,
историю и файлы. Прошли 10 браузерных сценариев сайта на компьютере
и телефоне: вход, выход, контакты, цитаты, редактирование,
подтверждение удаления, загрузка файла, реакции, поиск и восстановление
подключения. Сервер входа настоящий локальный, MAX API подменён.

На рабочем сайте с настоящим аккаунтом проверены открытие переписки,
показ фотографии и скачивание фотографии и документа.
Ошибок JavaScript в этом сценарии не обнаружено.

Для Mini App проверены подписанные Telegram-данные и отказ
для анонимного запроса или неверной подписи. На ширине 390 и 1280
проверены восстановление после перезагрузки и сбоя, а также вход
по одному ключу. Данные MAX подменены. Проверка выполнена
в отдельном браузере, а не в окне приложения Telegram.

Проверена подготовка локальных настроек: новые файлы создаются,
существующие не перезаписываются. Прошли проверка типов, границ FSD
и аудит зависимостей рабочего приложения.

Новые сообщения реальным получателям во время проверки не отправлялись.
Уведомления провайдера не подтверждались. Полную переписку с живым
получателем, редактирование, удаление, реакции, пересылку и загрузку файлов
нельзя считать проверенными на реальном аккаунте только по этим тестам.
Ручная проверка описана в инструкции запуска.

В тестах остаются пробелы. Нет полного браузерного сценария создания
чата по номеру. Пересылка и отметка прочтения проверяются на сервере,
но не полным действием через интерфейс. Экспорт истории не покрыт
отдельным сценарием. Для фото и видео есть проверки в Mini App;
они не заменяют проверку всех форматов в каждом браузере.

Кроме текста доступны чаты и контакты, групповые переписки, поиск,
история, файлы, просмотр фото, видео и аудио, цитаты, пересылка,
изменение и удаление своих сообщений, реакции, отметка прочтения,
экспорт загруженной истории и сохранение подключения.

Звонки, создание групп, управление участниками, запись голоса,
уведомления при закрытом сайте и постоянный архив всей переписки
не реализованы. Файл ограничен 10 МБ, история зависит от GREEN-API.

Сайт и Mini App сохраняют подключения отдельно.
Один инстанс должен иметь одного читателя очереди уведомлений.
При одновременном чтении ответы могут разделиться между клиентами.
Общего сервера, который раздаёт одни события нескольким клиентам,
в этой реализации нет.
