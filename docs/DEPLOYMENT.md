Локальный запуск и настройка Max.

Нужны Node.js 22.12 или новее, npm и Git. Это самостоятельный веб-клиент.
Для него не нужно устанавливать бота Советника, Telegram, PostgreSQL или Redis.
Для настоящей переписки нужен авторизованный аккаунт MAX в GREEN-API.

Проверьте инструменты в терминале:

```sh
node --version
npm --version
git --version
```

Скачайте проект и запустите его. Все дальнейшие команды выполняйте
из папки `max-green-api-client`.

```sh
git clone https://github.com/Webappmaster-Eugene/max-green-api-client.git
cd max-green-api-client
npm ci
npm run auth:setup
npm run build
npm run start:local
```

`npm ci` устанавливает зависимости. `auth:setup` создаёт настройки сервера
и первого пользователя. `build` собирает приложение. `start:local` запускает
его с настройками из `.env.local`.

Откройте http://127.0.0.1:18792. Найдите логин и пароль в `.admin-credentials`,
открыв файл в редакторе. Это пароль сайта, а не ключ GREEN-API.
После первого входа смените пароль в настройках аккаунта.

`.env.local` содержит ключ подписи сессий и защищённый хеш начального пароля.
Хеш позволяет проверить пароль без хранения его исходного текста.
Оба файла создаются с правами 0600: читать и менять их может владелец файла.
Они исключены из Git и сборки Docker. Не публикуйте их и каталог `data/`.
Повторный запуск `auth:setup` не перезаписывает существующие настройки.

Чтобы подключить MAX, откройте [кабинет GREEN-API](https://console.green-api.com/).
Создайте или выберите инстанс MAX. Инстанс - это подключение аккаунта
в кабинете. Авторизуйте его по инструкции провайдера. Должен появиться
статус «Авторизован». Аккаунт подключает его владелец.

В настройках инстанса оставьте `webhookUrl` пустым. Включите уведомления
о входящих сообщениях и файлах, исходящих сообщениях с телефона и через API,
статусах доставки, редактировании и удалении. Клиент получает ответы
из HTTP-очереди. Подробности есть в [руководстве пользователя](USER_GUIDE.md).

Войдите на локальный сайт. Скопируйте из карточки инстанса `apiUrl`,
`mediaUrl`, `idInstance` и `apiTokenInstance` в форму подключения.
Это адрес API, адрес для файлов, номер инстанса и ключ GREEN-API.
Адреса могут совпадать. Используйте их точно как в кабинете.
Подтвердите разрешение владельца и нажмите «Подключить MAX».
Появятся существующие чаты и контакты.

Для проверки откройте чат или создайте новый по номеру телефона.
Отправьте текст человеку, который согласился помочь, и попросите ответить
из MAX. Ответ должен появиться в открытом диалоге. Затем прикрепите
небольшой JPG или TXT. Фото можно открыть, файл - скачать.
Сообщения отправляются от имени подключённого MAX-аккаунта.

Во время проверки не открывайте тот же инстанс в Mini App, на рабочем сайте
или в другом клиенте очереди. Уведомления выдаются одному читателю:
два клиента могут получить разные части ответов.

Остановить сервер можно через `Ctrl+C`. Чтобы запустить его снова:

```sh
npm run start:local
```

Повторять `auth:setup` и вводить все реквизиты MAX не нужно.
Сохраняйте `.env.local` и `data/`. Они нужны для входа и восстановления
подключений. После явного отключения MAX достаточно снова ввести ключ;
адреса и номер инстанса остаются сохранёнными. История загружается
из GREEN-API, а не восстанавливается из архива на диске.

Если `node` или `npm` не найдены, установите Node.js 22.12 или новее
и откройте новый терминал. Если настройки уже существуют, используйте их.
Пароль в `.admin-credentials` перестаёт действовать после его смены на сайте.

Если сервер не запускается, выполните `npm run build`, проверьте `.env.local`,
свободный порт 18792 и права записи в `data/`. Не удаляйте каталог данных
для исправления ошибки: вместе с ним пропадут пользователи и подключения.

Открывайте именно `http://127.0.0.1:18792`. Адрес `localhost` считается другим
адресом сайта и может привести к отказу в запросе. Если GREEN-API
не подключается, проверьте тип MAX, авторизацию и реквизиты инстанса.
Если ответы не приходят, оставьте вкладку видимой, проверьте настройки
уведомлений и отсутствие другого клиента очереди.

Ошибка 429 означает слишком частые запросы. Подождите и закройте другие
клиенты этого инстанса. Ошибка 466 означает исчерпанную квоту;
проверьте ограничения инстанса в кабинете. Повтор через несколько секунд
такую квоту не восстановит.

Для разработки сначала выполните установку и `auth:setup`, затем
откройте два терминала в папке проекта. В первом запустите сервер:

```sh
npm run dev
```

Во втором запустите интерфейс:

```sh
npm run dev:ui
```

Откройте http://127.0.0.1:5174. Сервер разработки принимает этот адрес,
а Vite передаёт запросы API на порт 18792. Используйте `127.0.0.1`
в обоих случаях. Обычный `npm start` получает настройки из окружения хостинга.

`PUBLIC_ORIGIN` задаёт адрес сайта без пути и завершающего `/`.
На хостинге нужен HTTPS. `AUTH_JWT_SECRET` - случайный ключ подписи
длиной не менее 32 байт, а не пароль пользователя.
`ADMIN_LOGIN` и `ADMIN_PASSWORD_HASH` создают первого администратора,
только если `users.json` ещё не существует. Хеш создаёт `auth:setup`.

`DATA_DIR` указывает постоянный каталог данных. В Docker это `/app/data`.
`HOST` в контейнере должен быть `0.0.0.0`, `PORT` - `3000`.
Для рабочего сервера задайте `NODE_ENV=production`.
Ключ GREEN-API вводится в форме сайта, а не в переменных окружения.

Чтобы разместить приложение в Dokploy, создайте Application из этого
репозитория, выберите ветку `main`, Dockerfile и контекст сборки `.`.
Укажите порт контейнера 3000. Добавьте домен и HTTPS.
`PUBLIC_ORIGIN` должен совпадать с адресом в браузере.

Перед первым запуском передайте `AUTH_JWT_SECRET`, `ADMIN_LOGIN`
и `ADMIN_PASSWORD_HASH` в закрытые настройки окружения Dokploy.
Используйте значения из локальной подготовки. Не записывайте их в Git
или Dockerfile.

Подключите постоянный volume к `/app/data`. Этот каталог должен быть
доступен пользователю node с UID 1000. Он сохраняет пользователей,
сессии, подключения MAX и ключи шифрования при замене контейнера.

Оставьте одну копию приложения. В Advanced, Swarm Settings задайте
`Order=stop-first` для Update Config и Rollback Config.
Сначала останавливается старая копия, затем запускается новая.
Это нужно, чтобы два процесса не записывали одни файлы одновременно.
Во время обновления возможен короткий перерыв в работе.

После Deploy проверьте `/health`, страницу входа и отказ 401
от `/api/max` без cookie с заголовком `X-Max-Client: 1`.
Затем проверьте вход и выход. Ответ `/health` сам по себе
не подтверждает работу авторизации или GREEN-API.

Сохраняйте защищённую резервную копию всего `DATA_DIR` и ключа
`AUTH_JWT_SECRET`. Для восстановления нужны файлы `.enc` вместе
с их файлами `.key`. `users.json` содержит логины, роли и хеши паролей.
История переписки в этом каталоге не архивируется.

Перезапуск не завершает сохранённый вход. После обновления старой версии,
которая хранила ключ только в памяти, MAX нужно подключить один раз заново.
Существующие пользователи не заменяются начальными настройками.

Перед публикацией изменений запустите проверки:

```sh
npm run format:check
npm run smoke
npm test
npm run test:ui
npm run build
npx playwright install chromium
npm run test:e2e
docker build -t max-client .
```

Серверные тесты проверяют вход, права, сохранение сессий, защиту файлов
и сообщения. Тесты интерфейса проверяют формы и обработку ошибок.
Playwright открывает приложение на компьютере и телефоне с подменённым
MAX API. Эти проверки не отправляют сообщения реальным людям.
CI запускает проверки из `.github/workflows/ci.yml`.
